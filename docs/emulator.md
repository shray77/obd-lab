# Тестовый стенд: ELM327-emulator

Полноразмерный эмулятор ELM327 + «машины» (Ircama/ELM327-emulator) используется
только для проверки `Elm327Channel` против чужой реализации стандарта.
Это не наш код и не зависимость продукта.

## Лицензия

ELM327-emulator распространяется под **CC BY-NC-SA 4.0** — некоммерческая.
Поэтому:

* ставится отдельно, вручную: `pip install ELM327-emulator`
  (обязательно с `PYTHONUTF8=1`, иначе pip падает на кириллическом README пакета);
* **не добавляется** в `requirements.txt` и не линкуется в продукт;
* модуль называется `elm` (не `elm327_emulator`), CLI — `elm`.

## Запуск стенда

    $env:PYTHONUTF8=1
    python tools/run_elm_emulator.py 35000 car "0171,2187,0420"

* `35000` — TCP-порт; наша программа подключается как `--port socket://127.0.0.1:35000`;
* `car` — сценарий «машины» (есть ещё `default`, `engineoff`, `mt05`);
* третий аргумент — DTC, подмешанные в блоки 03/07/0A. **Аргумент брать в
  кавычки**: PowerShell без кавычек превращает `0171,2187,0420` в массив чисел
  и срезает ведущие нули (`171`), а эмулятор молча выбрасывает элементы с
  нечётной длиной — получим «тихо пропавший» код.

Проверка нашим стеком:

    python -m obd_lab.live --port socket://127.0.0.1:35000
    python tools/probe_elm_emulator.py        # сырые ответы эмулятора
    python -m unittest discover -s tests      # интеграционные тесты
                                              # сами пропустятся без эмулятора

## Найденные особенности эмулятора (и как их учёл наш код)

1. **Блок 03/07/0A без байта-счётчика.** ISO 15765-4 требует
   `43 <число> <коды...>`, эмулятор шлёт `43 <коды...>` (и `43 00` на пустой).
   На реальном CAN такой формат существовал бы только как отклонение, но часть
   блоков и правда его шлёт. `decode_dtc_block` различает форматы: в
   счётчиковом формате длина блока всегда нечётная (счётчик + пары байт +
   нулевая добивка), чётная длина — значит блок без счётчика.
   Кейс: `43 01 71 21 87 04 20` — это P0171/P2187/P0420, а не один C3121.
2. **Широковещательный 09 02 «циклит» VIN.** Сценарий `car` эмулирует три ЭБУ
   с разными VIN и отдаёт их по очереди на каждый запрос — VIN меняется от
   запроса к запросу. На реальной машине VIN один; наш фильтр
   `response_id=0x7E8` отсекает чужие адреса, а «цикл» — чистый артефакт
   эмулятора, клиентом не лечится.
3. **UDS не поддерживается** (19 02, 22 F1 90 → `NO DATA`). Это полезно:
   именно здесь проверяется наш fallback на OBD-режимы 03/07/0A и 09 02.
4. **Резкий разрыв соединения валит эмулятор** (лавина WinError 10053, порт
   перестаёт принимать). Все наши инструменты (`probe_elm_emulator.py`,
   интеграционные тесты, `live.py`) перед close делают
   `socket.shutdown(SHUT_RDWR)`. Между сессиями эмулятор лучше перезапускать.
5. **`elm` в интерактивном режиме умирает при закрытии stdin** — поэтому
   поднимаем его через API (`Elm(net_port=...)` как context manager), а не
   через CLI. `-v` — это уровень логирования (число), не файл.

## Что стенд подтвердил в нашем коде

* `ATDPN` → «CAN 11 бит, 500 кбит/с», атрибут `count_byte=True`;
* ATRV → напряжение АКБ (13.1–13.3 В);
* `0100` (поддержка PID) и `0101` (MIL-бит реагирует на подмешанные DTC);
* блоки 03/07/0A в обоих форматах (со счётчиком и без);
* VIN через мультифрейм 09 02 (обе раскладки: с номером строки и без);
* UDS→OBD fallback на «чужом» ЭБУ;
* `decode_dtc_block` различает счётчик и первый код, если они похожи.
